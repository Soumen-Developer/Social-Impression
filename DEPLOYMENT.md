# Social Impression - Deployment Guide for Render

## Overview
This guide covers deploying the Social Impression Next.js application to Render.com with PostgreSQL database.

## Prerequisites
- GitHub/GitLab account with the repository
- Render.com account
- Domain name (optional, for custom domain)

## 1. Database Setup (PostgreSQL on Render)

### Option A: Using render.yaml (Recommended)
The `render.yaml` file in the project root defines all services. To deploy:

1. Push your code to GitHub/GitLab
2. Go to Render Dashboard → New → Blueprint
3. Connect your repository
4. Render will automatically create:
   - PostgreSQL database (`social-impression-db`)
   - Web service (`social-impression-web`)
   - Background worker (`social-impression-worker`)
   - Cron jobs for maintenance

### Option B: Manual Setup
If you prefer manual setup:

1. **Create PostgreSQL Database:**
   - Dashboard → New → PostgreSQL
   - Name: `social-impression-db`
   - Database: `social_impression`
   - User: `social_impression`
   - Plan: Starter (or higher)
   - Region: Singapore (closest to India)
   - Version: 16

2. **Create Web Service:**
   - Dashboard → New → Web Service
   - Connect repository
   - Runtime: Docker
   - Dockerfile Path: `./Dockerfile`
   - Plan: Starter
   - Region: Singapore
   - Health Check Path: `/api/health`

3. **Environment Variables (Web Service):**
   ```
   NODE_ENV=production
   NEXT_TELEMETRY_DISABLED=1
   PORT=3000
   HOSTNAME=0.0.0.0
   DATABASE_URL=<from database connection string>
   SESSION_SECRET=<auto-generated>
   WEBHOOK_SECRET=<auto-generated>
   APP_URL=https://your-app.onrender.com
   ```

## 2. Required Environment Variables

### Critical (Must Set)
| Variable | Description | Source |
|----------|-------------|--------|
| `DATABASE_URL` | PostgreSQL connection string | Render Database service |
| `SESSION_SECRET` | 32+ char random string | Generate: `openssl rand -base64 32` |
| `WEBHOOK_SECRET` | Webhook verification secret | Generate: `openssl rand -base64 32` |
| `APP_URL` | Your production URL | `https://your-app.onrender.com` |

### Email (Required for Auth)
| Variable | Description |
|----------|-------------|
| `SMTP_HOST` | SMTP server (e.g., smtp.sendgrid.net) |
| `SMTP_PORT` | Usually 587 |
| `SMTP_USER` | SMTP username |
| `SMTP_PASS` | SMTP password |
| `EMAIL_FROM` | From address (e.g., "Social Impression <noreply@domain.com>") |

### Payment Gateways (Required for Purchases)
**Razorpay (India):**
- `RAZORPAY_KEY_ID`
- `RAZORPAY_KEY_SECRET`
- `RAZORPAY_WEBHOOK_SECRET`

**Stripe (International):**
- `STRIPE_SECRET_KEY`
- `STRIPE_PUBLISHABLE_KEY`
- `STRIPE_WEBHOOK_SECRET`

### Social Auth (Optional)
- `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`
- `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET`

## 3. Post-Deployment Setup

### Run Database Migrations
After first deploy, run migrations:
```bash
# In Render Shell (web service)
npx prisma migrate deploy
```

### Seed Initial Data (Optional)
```bash
# In Render Shell
npx tsx prisma/seed/seed.ts
```

### Verify Deployment
1. Check health endpoint: `https://your-app.onrender.com/api/health`
2. Test login with demo credentials:
   - Admin: `admin@socialimpression.in` / `demo1234`
   - Artist: `mira@socialimpression.in` / `demo1234`

## 4. Custom Domain (Optional)

1. In Render Web Service → Settings → Custom Domains
2. Add your domain (e.g., `socialimpression.in`)
3. Update DNS records as instructed
4. Update `APP_URL` environment variable to your custom domain
5. Redeploy

## 5. SSL/HTTPS
Render provides automatic SSL for `*.onrender.com` and custom domains.

## 6. Monitoring & Logs
- View logs in Render Dashboard → Service → Logs
- Health checks run every 30s on `/api/health`
- Set up external monitoring (UptimeRobot, Pingdom) if needed

## 7. Scaling
- **Starter Plan**: 512MB RAM, 0.5 CPU
- **Standard Plan**: 1GB RAM, 1 CPU (recommended for production)
- **Pro Plan**: 2GB+ RAM, 2+ CPU

For production traffic, upgrade to Standard or Pro.

## 8. Database Backups
Render provides daily backups on paid plans (7-day retention).
For additional safety, consider:
- Point-in-time recovery (Pro plans)
- Manual pg_dump via cron job

## 9. Troubleshooting

### Build Fails
- Check Node version compatibility (uses Node 20)
- Ensure all dependencies in package.json
- Check build logs for TypeScript errors

### Database Connection Issues
- Verify DATABASE_URL format: `postgresql://user:pass@host:port/db`
- Check database is in same region as web service
- Ensure database allows connections from web service

### Health Check Fails
- Verify `/api/health` endpoint returns 200
- Check database connectivity in health endpoint
- Increase health check timeout if needed

### Memory Issues
- Upgrade to Standard/Pro plan
- Check for memory leaks in application code
- Add `--max-old-space-size` to Node if needed

## 10. CI/CD Pipeline
The render.yaml enables automatic deployments on push to main branch.
For manual control, disable auto-deploy in service settings.

## 11. Local Development with Production-like Setup

### Using Docker Compose (Optional)
Create `docker-compose.yml`:
```yaml
version: '3.8'
services:
  app:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DATABASE_URL=postgresql://postgres:postgres@db:5432/social_impression
      - SESSION_SECRET=local-dev-secret
      - WEBHOOK_SECRET=local-webhook-secret
    depends_on:
      - db
  
  db:
    image: postgres:16-alpine
    environment:
      - POSTGRES_DB=social_impression
      - POSTGRES_USER=postgres
      - POSTGRES_PASSWORD=postgres
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:
```

Run: `docker-compose up --build`

## 12. Important Notes

### SQLite vs PostgreSQL
- **Development**: Uses SQLite (`file:./dev.db`)
- **Production**: Uses PostgreSQL (Render managed)
- Prisma schema supports both providers

### File Uploads
For production file uploads, configure:
- AWS S3 / Cloudflare R2 / Supabase Storage
- Update upload logic to use cloud storage
- Local filesystem won't persist on Render

### Webhooks
Configure webhook URLs in payment providers:
- Razorpay: `https://your-app.onrender.com/api/webhooks/razorpay`
- Stripe: `https://your-app.onrender.com/api/webhooks/stripe`
